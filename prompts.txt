PHASE 1: Graph Builder & Fraud GPS Engine

Continue building the Fraud GPS project. The data from Phase 0 should already exist.

Build the following backend modules:

1. `engines/graph_builder.py`:
- Load all JSON data files on startup
- Build a NetworkX DiGraph where:
- Nodes = bank accounts (with all attributes as node data)
- Edges = transactions (with amount, timestamp, channel as edge data)
- Also build an "entity linkage graph" — a separate graph where:
- Nodes = accounts + entities
- Edges = "account uses entity" relationships
- Provide helper functions:
- get_node_data(account_id) → full account info + computed stats
- get_neighbors(account_id) → immediate connections
- get_subgraph(account_id, depth=3) → N-hop neighborhood
- get_linked_complaints(account_id) → complaints involving this account

2. `engines/fraud_gps.py` — The Money Trail Tracer:
- `trace_money_trail(start_account, start_tx_id=None, max_depth=5)`:
- Perform a BFS/DFS forward trace from the victim's account
- Follow outgoing transactions chronologically
- For each hop, record: from, to, amount, timestamp, channel
- Return an ordered list of "trail steps" with the full path

- `detect_splits(trail)`:
- Find nodes where 1 incoming transaction leads to 2+ outgoing transactions within 30 minutes
- Return list of split events: {node, incoming_amount, outgoing_amounts[], time_gap}

- `detect_rapid_forwards(trail)`:
- Find nodes that forwarded >80% of received amount within 30 minutes
- Return list of rapid-forward events

- `detect_layering_chains(trail)`:
- Find sequential chains of 3+ pass-through nodes
- Return chains with total time and amount decay

- `detect_cashout_terminals(trail)`:
- Find terminal nodes (no significant outgoing transactions after receiving)
- Return list of probable cash-out accounts

- `classify_node_role(account_id)`:
- Based on graph features, classify as one of:
- "Collector": high fan-in from unrelated senders
- "Splitter": receives large, sends multiple smaller
- "Layering Node": ~equal in and out, fast forward
- "Hub": high betweenness centrality, connects sub-networks
- "Cash-Out": terminal node, no onward transfer
- "Bridge": appears in multiple complaint trails
- "Normal": no suspicious indicators
- Return role + confidence + reasons

3. `engines/risk_scorer.py`:
- `compute_risk_score(account_id)`:
- Compute a composite risk score (0.0 to 1.0) based on:
a) Transaction anomaly score (0.20 weight):
- inflow/outflow ratio, rapid forwarding, amount fragmentation
b) Graph position score (0.20 weight):
- betweenness centrality, degree centrality in suspicious subgraph
c) Complaint linkage score (0.20 weight):
- direct or N-hop connection to complaint-linked accounts
d) Temporal burst score (0.15 weight):
- sudden spike in transaction volume vs historical baseline
e) Dormancy reactivation score (0.10 weight):
- long inactive period followed by sudden burst
f) Entity overlap score (0.15 weight):
- shares phone/device/UPI with other suspicious accounts
- Return: total_score, component_scores{}, risk_level ("Low"/"Medium"/"High"/"Critical")

- `score_all_nodes()`:
- Score every account in the graph
- Cache results

4. `engines/explainer.py`:
- `generate_explanation(account_id, risk_data)`:
- Generate a list of human-readable bullet points explaining WHY this account is suspicious
- Example output:
[
"Received ₹2.3L from 47 unrelated accounts in 4 hours",
"Forwarded 94% of received funds within 30 minutes of receipt",
"Linked to 6 active fraud complaints",
"Account was dormant for 52 days before sudden activation",
"Shares device ID with 3 other flagged accounts"
]
- Make the explanations specific (use real numbers from the data, not generic text)

- `generate_case_summary(complaint_id)`:
- Generate a 3-5 sentence narrative summary of the fraud trail
- Should read like an investigation report paragraph
- Example: "On 2024-09-15, victim Rajesh Kumar (Account XXXX1234, SBI Patna) transferred ₹50,000 via UPI to account XXXX4521..."

5. Create API routes:

`routes/trace.py`:
- POST /api/trace — accepts {complaint_id} or {account_id}, returns full trail data including path, splits, layering, cash-outs, and node roles

`routes/risk.py`:
- GET /api/risk/{account_id} — returns risk score, components, level, role, and explanation
- GET /api/risk/top?limit=20 — returns top N riskiest accounts

`routes/graph.py`:
- GET /api/graph/full — returns full graph data (nodes + edges) in a format ready for Cytoscape.js:
```json

"nodes": [{"data": {"id": "...", "label": "...", "risk_score": 0.9, "role": "Splitter", ...}}],
"edges": [{"data": {"source": "...", "target": "...", "amount": 50000, "timestamp": "...", ...}}]
}
```
- GET /api/graph/subgraph/{account_id}?depth=3 — returns N-hop subgraph around an account
- GET /api/graph/trail/{complaint_id} — returns only the nodes and edges in the traced money trail

`routes/timeline.py`:
- GET /api/timeline/{complaint_id} — returns ordered list of events for timeline playback:
```json
[
{"step": 1, "type": "transfer", "from": "XXXX1234", "to": "XXXX4521", "amount": 50000, "timestamp": "...", "label": "Victim sends ₹50K via UPI"},
{"step": 2, "type": "split", "node": "XXXX4521", "outputs": [...], "timestamp": "...", "label": "Fund split into 3 accounts"},
...
]
```
